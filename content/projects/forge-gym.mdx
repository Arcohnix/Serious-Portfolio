overview: |
  ForgeGym is an Android training journal for managing workout routines and tracking completed sessions. Users can record sets with weight and repetitions, pause or resume an active session, use a rest timer, and review training history and progress summaries.

  The application stores workout and session records in a Room database. Progression recommendations are calculated from prior performance using user-selected strategies and one-rep-max formulas; they are deterministic application logic rather than machine-learning predictions. The app also includes JSON backup import/export and CSV history export.
problemStatement: |
  Workout tracking needs to connect routine setup, in-session logging, and later review without making training data dependent on a network connection. ForgeGym brings those tasks into one Android application with local persistence.
engineeringGoals:
  - Organize the Android app around UI, ViewModel, repository, and local data layers.
  - Persist workout plans, active and completed sessions, set records, and personal records with Room.
  - Provide configurable, rule-based progression recommendations and training history views.
  - Support JSON backup and CSV history export from the application.
architecture:

      tech: Kotlinx Serialization JSON and CSV
      desc: Encodes backup data as JSON, restores supported records in a Room transaction, and exports completed workout history as CSV.

decisions:
  - title: Keep Workout Records in a Local Room Database
    decision: Store workout plans, sessions and set records using Room, with DataStore for preferences.
    why: The app can manage training records locally without requiring a remote service for its core tracking flow.
    tradeoff: The repository does not implement account-based or server synchronization, so data portability relies on the available backup and export features.
  - title: Calculate Progression Suggestions with Explicit Rules
    decision: Use selectable progression strategies and one-rep-max formulas to calculate recommendations from recorded performance.
    why: The recommendation path is deterministic and its calculation rules are represented directly in the application code.
    tradeoff: Recommendations depend on the user's logged data and configured strategy; they are not a trained model or a guarantee of training outcomes.
challenges: []
lessons:
  - title: Active sessions need persisted state
    content: Storing an unfinished session and its completed sets in the local database allows the application to observe an active workout after the screen state changes.
  - title: Recommendations should be described by their method
    content: ForgeGym computes progression suggestions with explicit formulas and strategies, so they should be understood as rule-based guidance rather than learned predictions.
  - title: Export supports user-managed portability
    content: JSON backup and CSV history export give users ways to take copies of their training records without implying cloud synchronization.

ForgeGym is an Android application built with Kotlin and Jetpack Compose. Its manifest declares vibration permission and does not declare internet permission; the repository includes unit tests for progression and one-rep-max calculations.
