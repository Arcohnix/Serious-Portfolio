  Engineers and support teams spend hours searching across fragmented, out-of-date documentation wikis. problemStatement: |
  Pure vector similarity searches often miss exact keyword codes, error IDs, and version numbers. Without strict grounding verification, generative models synthesize plausible but fabricated answers from incomplete context.
engineeringGoals:
  - Combine semantic vector retrieval with exact BM25 keyword matching using Reciprocal Rank Fusion (RRF).
  - Implement a secondary cross-encoder re-ranking phase to filter low-relevance context chunks.
  - Enforce strict citation requirements, rejecting answers that cannot be directly supported by retrieved context.

workflowSteps:
  - step: "01"
    title: Document Chunking & Ingestion
    description: Internal guides and specifications are normalized into structured chunks preserving section headings, metadata tags, and code blocks.
  - step: "02"
    title: Dual-Vector & Keyword Indexing
    description: Each chunk is simultaneously converted into dense vector embeddings and registered into a sparse lexical inverted index.
  - step: "03"
    title: Hybrid Query & Rank Fusion
    description: When a user query arrives, both indices execute in parallel. Results are merged and scored using Reciprocal Rank Fusion (RRF).
  - step: "04"
    title: Cross-Encoder Re-Ranking
    description: The top 20 candidate chunks pass through a cross-encoder model that evaluates deep semantic relevance, pruning the context down to the top 4 chunks.
  - step: "05"
    title: Grounded Synthesis with Strict Citations
    description: The model synthesizes the answer strictly using the provided context, appending clickable source references and refusing to extrapolate when facts are absent.
decisions:
  - title: Hybrid Retrieval (Dense + BM25) over Pure Vector Search
    decision: Merged sparse BM25 indexing with dense semantic embeddings.
    why: Vector embeddings frequently fail to retrieve exact error numbers (e.g. 'ERR_CONN_404') and specialized API methods, while BM25 guarantees exact keyword hits.
    tradeoff: Requires maintaining two indices and running rank fusion scoring during query execution.
  - title: Two-Stage Re-Ranking over Raw Top-K Selection
    decision: Added a cross-encoder re-ranking step before assembling the LLM context window.
    why: Bi-encoder retrieval is fast but imprecise. Cross-encoders accurately discard subtly irrelevant chunks that cause LLM distraction.
    tradeoff: Adds approximately 60ms of latency per query during the re-ranking stage.
challenges:
  - title: Conflicting Information Across Document Versions
    scenario: Legacy documentation files contained outdated configuration parameters that contradicted modern guidelines.
    risk: The assistant generated deprecated commands alongside modern procedures.
    mitigation: Incorporated document timestamp metadata and canonical version tagging into the re-ranker scoring formula.
  - title: Hallucinated Citations
    scenario: When context lacked explicit answers, the LLM hallucinated fictitious section numbers.
    risk: Loss of engineer trust in generated answers.
    mitigation: Built an automated post-generation verification step that validates whether cited section IDs exist in the retrieved context chunks.

    def reciprocal_rank_fusion(dense_results, sparse_results, k=60):
        scores = defaultdict(float)
        for rank, doc_id in enumerate(dense_results):
            scores[doc_id] += 1.0 / (k + rank + 1)
        for rank, doc_id in enumerate(sparse_results):
            scores[doc_id] += 1.0 / (k + rank + 1)

        # Sort by merged relevance score
        ranked_ids = sorted(scores.keys(), key=lambda x: scores[x], reverse=True)
        return ranked_ids[:10]
